## 当前行为

1. 超级管理员进入“用户管理 → 邀请与注册审批”，创建绑定邮箱的一次性邀请。
2. 将生成的注册链接私下发给对应用户。链接中的邀请码仅显示一次，默认有效 7 天。
3. 用户提交申请后处于待审批状态，此时没有可登录的用户或 API 令牌。
4. Mailjet 向服务器私密配置中的审批邮箱发送通知；管理员在后台批准或拒绝。
5. 批准后创建普通用户并分配邀请指定的初始额度，用户才能登录和创建自己的模型令牌。

邮件显示名显式留空（`SMTP_FROM_NAME=`），只显示发件邮箱。
实际发件地址、审批收件人、SMTP 凭据及平台密钥仅保存在服务器私密配置或受限数据库中。
`INVITATION_REGISTRATION_ENABLED=true`，注册总开关和密码注册开关均已启用，公开入口仍强制邀请和审批。
OAuth/微信新账号创建不能绕过此策略；原有绑定账号可继续登录。
邮件中的链接必须登录管理员后处理，GET 请求或邮件扫描器不会批准申请。

## 已完成验收

- model/controller/router/service 完整回归测试、冻结依赖的前端构建和 Go 程序构建通过。
- 候选版本使用现有 SQLite 数据库副本，在独立端口和受限服务中完成实际 HTTP 验收。
- 无邀请、邮箱不匹配、邀请码已使用、撤销、过期均被拒绝。
- 待审批账号不能登录且没有正式 User；批准后可登录，仅具有普通用户权限，不能访问审批数据。
- 批准后的普通用户可创建模型受限令牌；重复审批被拒绝。
- 拒绝后不能登录，不创建正式用户，并清除申请密码哈希和待处理唯一性占位。
- 两次启动验证迁移可重复执行；现有用户、令牌及渠道的凭据和权限保持一致，SQLite integrity_check 为 ok。
- 真实注册通知通过 Mailjet 发送，管理员已确认收到；测试账号仅存在数据库副本中。
- 重复测试触发了已有频率限制；对限流返回与权限拒绝遵循现有平台 API 约定进行核对。
- 正式上线前备份数据库、私密配置及服务单位；先确认新版本邀请策略，再打开申请入口。
- 上线后公网状态显示新版本和邀请策略，注册页面 HTTP 200，无令牌模型列表 HTTP 401。
- 正式库没有验收测试账号或申请；既有令牌的模型列表和一次最小文本推理成功。
- 网关就绪、活动请求回到 0，全局并发上限仍为 4；原 GPU 模型作业和科研调度配置未重启或改动。
- 只重启了 API 管理平台。MySQL/PostgreSQL 未进行实例运行测试，当前部署实际使用 SQLite。

完整的建库、注册、审批测试仅在副本进行；正式库收尾使用只读检查及既有账号正常推理。
验收摘要见 [发布记录](evidence/new-api/invitation-release.json)。

- 发布切换：`/etc/systemd/system/new-api.service.d/50-prlab-release.conf`，仅覆盖 ExecStart。
- CPU、内存、设备、文件系统隔离与原网络拒绝规则保留；Mailjet 精确地址许可位于独立 `40-mailjet.conf`。

- 数据库、配置及原服务单位的上线前备份：私密 `backups/release-时间戳/` 目录。
- 候选构建与副本验收目录位于独立 `new-api-build/` 中；副本服务验收后已停止。
- API 平台“服务器地址”已更新为实际 HTTPS 站点，审批通知链接可以从公网打开。
- 少数默认自动客户端 User-Agent 被现有 Cloudflare 策略返回 403/1010；普通网页与应用标识请求已验证可达。
  此次没有修改 Cloudflare 的安全策略；如某客户端遇到此错误，按该请求的标识和规则定位，不盲目关闭保护。

回滚前必须先在新版本关闭注册总开关和密码注册开关；旧上游版本不识别邀请策略。
保留现有数据时，可恢复旧程序及匹配的 VERSION 环境，并移除或恢复发布专用 drop-in，再 daemon-reload、只重启 New API。
新表可保留，不要在有新注册数据后直接用上线前数据库覆盖正式库。
只有确认上线后没有需要保留的数据或已安排完整迁移时，才恢复匹配的数据库备份。
服务器上保留了本次带失败自动回滚的私密部署脚本与发布记录；它们不会在正常运行时自动回滚或重放注册测试。
