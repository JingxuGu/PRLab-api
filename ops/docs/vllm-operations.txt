  后端：http://127.0.0.1:8001，另有独立密钥，客户端应使用入口。
  /v1/chat/completions：文本、图片、工具调用和 SSE 流式输出。
  /v1/completions：文本补全；/v1/models：模型列表。
  六个客户端密钥位于 /home/llmops/llm/config/client-keys.json，权限 0600。
  user01 到 user06 是分发标签，由管理员通过私下渠道分别分发。

  密钥未写入部署说明、命令参数或聊天。
  全局最多四个已接纳生成请求；第五个立即返回 HTTP 429，可稍后重试。
  四人共用一个模型实例，vLLM max-num-seqs=4。
  不接纳 n>1、best_of>1 或批量文本提示，避免一个请求展开为多路生成。
  入口仅运行一个 worker；增加 worker 会破坏当前全局四请求计数。
  请求体上限 8 MiB；上下文为 16,384 token，包含图片与输出预算。
  每个请求最多一张图片，处理后最大约 1,048,576 像素；视频未启用。
  关闭 CUDA Graph（enforce-eager），避免单张 5090 启动图捕获的显存峰值。
  KV 缓存初始保留模型原生精度；GPU 内存预算为 90%，实际以启动和并发验证为准。
  推理日志不记录请求正文；入口访问日志关闭。

Python 客户端示例（在有 openai 包的客户端环境中运行）
  from getpass import getpass
  from openai import OpenAI
  client = OpenAI(base_url="http://127.0.0.1:18000/v1", api_key=getpass("API Key: "))
  r = client.chat.completions.create(
      model="qwen3.8-27b",
      messages=[{"role":"user","content":"请简短介绍你自己。"}],
      max_tokens=512,
      extra_body={"chat_template_kwargs":{"enable_thinking":False}},
  )
  print(r.choices[0].message.content)
  图片使用 OpenAI 格式 content 数组中的 image_url，支持客户端将图片编码为 data URL。
  工具调用只返回工具选择与参数，服务器不会执行客户端工具。

调度与科研保护
  模型作为 llm 分区的一个完整 GPU 作业运行，作业名 qwen38-vllm。
  请求 8 个逻辑 CPU、28,000 MiB 主存、1 张 RTX 5090，最长 24 小时。
  research 优先级高于 llm，可终止并重新排队模型作业，释放显存。
  不采用暂停进程后保留显存的共享方式。
  被抢占时当前请求可能中断；入口在后端停止或启动期间返回 HTTP 503。
  被重新排队的作业默认约 120 秒后才具备调度资格，再等待资源和模型重新加载。
  120 秒不是服务恢复总时长，也不是科研作业启动时延承诺。
  稳定入口不申请 GPU；模型被抢占时它继续运行，提供就绪状态。
  模型作业正常到期后，管理服务会延迟 120 秒再提交一个新作业。
  异常重复启动三次/30 分钟后管理服务停止重试，需要管理员排查。
  后续所有 GPU 计算任务仍须通过 Slurm 提交。调度外的新任务和 root 可以绕过隔离。
  桌面图形进程保留，不受本次服务管理。
